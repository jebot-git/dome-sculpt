# Explicit source color preparation

This work adds a reversible static COLOR_0 preparation policy. It does not claim COLOR_n or TEXCOORD_n morph-channel support. Existing POSITION/NORMAL/TANGENT morph and skin authority stays separate.

## User action and retained data

Native Bake surface offers **Prepare source colors** and a maximum color error. The XR Baking page has the same staged choices under **Color policy** (cell9). Projection policy stays cell11; Save remains available in the universal menu, root spatial menu and Ctrl+S. Configuration and cancellation do not change history. Accepted preparation and bake form one document Undo operation.

The first conversion keeps the exact prior paint/UV, appearance, deformation and material binding. The original model bytes and static source color accessor are unchanged. Clear Bake does not remove this preparation. Repeat bake and UV adoption retain the first receipt and origin, and regenerate only the current projection from explicit remapped source identities. Native save/reopen retains both. A standalone UI action to restore the retained preconversion snapshot after reopening is not implemented yet; ordinary global Undo covers the current editing session. There is no automatic source whitening, division by color or alpha, or flattening of editable layers.

A separate resolved PBR RGBA plane carries the original linear vertex color exactly once. The ordinary paint/component plane remains available for typed MToon correction, whose versioned shaders ignore vertex colors. Each optional PBR paint tile follows the same layer order, visibility, opacity, coverage, undo and cancellation semantics. Zero RGB and zero alpha are handled without inversion. A new same-hit bake option writes both planes from the same projection hit and coverage. The default low-level bake API retains its previous vertex-color multiplication behavior.

The stored receipt explicitly distinguishes an original accessor from an identity source field. Identity preparation is an explicit native action; it cannot erase an authored accessor. Its measured projection-error bound is a bound on static source RGBA versus the linear RGBA8 projection, not a universal material, mip or lighting error bound. Complete base-color samples are separately recorded at declared LOD0 probes. A user-selected accepted bound follows later UV projections; first measurements remain immutable. Deep validation rechecks field authority and recorded quality rather than trusting descriptive metadata.

## Native formats and resource accounting

Prepared paint requires Scene10 and source-material archive3. Writer selection takes the maximum feature version, including existing Scene11 authored inverse binds, affine state and original source receipts inside retained origins/preparation bindings. Earlier versions reject new payloads. Resolved baked color uses baked payload2. Original-accessor/identity receipts are version1 with strict keys. Shared images, optional PBR tiles, resolved baked planes, retained paint and deformation participate in storage and validation budgets. The immutable proof cache uses weak owner authentication and cannot keep an avatar alive or accept an address-reuse hit.

Scene12 polygon integration must compose both bounded origin graphs and their retained-payload budgets; copying only active object fields is insufficient. The current checkpoint does not authorize dropping current source colors during arbitrary polygon topology edits. That requires an explicit current-field adapter and remap/projection receipt.

## Normal basis policy

New native bakes can capture an existing CanonicalMikk frame only after actual computed Mikk directions exactly match the retained PBR base and the conservative existing export proof applies: constant directions within each triangle, zero direction-target deltas, and one rigid joint per triangle. Original PBR/MToon direction owners remain unchanged. The captured frame is reused when sampling UVs later rotate, including repeat bake. This never relabels a historical baked normal payload.

Curved artist directions, nonzero normal/tangent morph deltas, mixed-joint cases and incompatible material frames remain guarded for standard export/UV transfer. Existing native dynamic canonical preview stays available for historical bakes. One standard glTF primitive has one NORMAL/TANGENT target basis; a static normal-map conversion between independently varying bases is not generally invariant under morphing and anisotropic skinning. A successful planar authored fixture does not prove arbitrary CC0 avatar normal conversion.

The next broader route is a separately versioned **new bake encoded in the retained original frame**, with native preview using that declared interpretation from creation. It needs exact format-specific shader interpolation, inverse-basis encoding, matching PBR/MToon attribute authority, per-channel coverage, pose and independent consumer proof. It must not reinterpret old canonical payloads. Arbitrary topology changes, UV1 source maps and actual COLOR/UV morph channels remain separate required work.
