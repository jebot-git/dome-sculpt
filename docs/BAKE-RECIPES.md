# Saved bake recipes

Each target now retains its last successful bake settings and the explicitly
chosen source and optional editable cage. Opening a native project restores
those settings. **Use last bake** in the existing desktop dialog and **Recall
last bake** in the XR Source / cage panel restore a local draft. Cancel discards
the draft; Done accepts settings without starting a bake or adding document
history. An explicit Bake remains necessary and replaces the recipe only after
successful projection, validation and publication.

The stored source/cage references include their original identity and name.
Deleting an object or nested group marks affected current and retained recipe
bindings unavailable. Removing only a group preserves live bindings. Package
append rebases references to the appended objects; exporting a subset marks
omitted dependencies unavailable. Coincident destination IDs and matching names
never reconnect missing dependencies. Source geometry, paint, locks and visibility
remain independently editable and are not changed by recalling a recipe.

Actual recipes use Scene30 and retained polygon-source archive7. Strict field,
UTF-8, integer, finite/range and actual-capability checks apply. Projects without
recipes retain their previous format and byte-identical output in the recorded
legacy fixtures. The published Scene29 readers explicitly reject Scene30;
opening a new recipe-bearing project with an older binary is unsupported.
The C++ object/control layouts change and require coherent consumer rebuilds.

nested group deletion, saved missing dependencies and controller staging. Nine
current native bake consumers pass in each profile, retaining the original32
cage and29 polygon-cage checks,47 source/cage confirmation allocation prefixes

Confirm62, object deletion16 and group deletion21 prefixes per profile. Three

preserves the exact old target/source and retries to the positive endpoint. No
product fault hook or error-policy relaxation is introduced.

Actual native FLTK input passes16 normal and16 compact checks per profile;
Wayland through a private nested DomeD compositor passes9 each. The current
matching application passes22 actual-loader stereo/controller checks each:
projection bounds are first changed, the saved recipe is recalled by ray, then
confirmed and explicitly baked. Cancel and focus loss preserve the full Scene.
All three XR native outputs and both GLB outputs are byte-identical across
profiles. Both recalled dialog layouts were visually inspected. This is
synthetic XR input, not a physical-headset test.

The sanitizer XR application uses the separately staged Mesa rtasm lifetime
patch. Actual mappings of all three clients prove that driver/EGL and the

## Build and resource boundaries

The application/core/render/support closure belongs to this new recipe layout.
The original fresh builds compiled the complete core/support but stopped on a
new palette identifier error. Complete corrected Scene and palette translation
units, remaining frontend/render/XR units and actual generated Wayland protocol
sources were then compiled and linked against those own matching archives.
No archive from an earlier recipe layout is borrowed. These are audited owning
build continuations and matching-component checks, not another fresh ALL build
or a claim that all612 currently registered tests passed.

Recipe names are limited to256 UTF-8 bytes before copying, DTO field counts and
numeric bounds are strict, and existing Scene object/history limits bound the
number of records. Snapshots share const recipe owners. Actual native payloads
continue through the existing prospective CBOR byte caps and strict read limits.
The source/material compiler's working budget is not a total native JSON heap
bound; broader allocator-null, worker and production resource qualification is
still required.

Preserved negatives include the original palette and test-include compiler
failures, two genuine Scene30/history7 round-trip rejections fixed in the complete
Scene TU, omitted protocol code generation in the first app completion, the first
GUI driver's unsupported Home-key navigation, and the first fault fixture's
nested-main include error. The corrected popup driver uses observed current
selection plus supported arrow keys. Older source-preservation fixtures now
compare the complete independently encoded readonly source Scene, with typed
owner checks, instead of comparing object records whose optional fields depend
on the changed target's global format. No source fields are filtered out.

The [machine-readable receipt](validation/BAKE-RECIPES.json) pins source,
application/archive/SDK/evidence hashes, actual commands, original negatives and
per-profile scope. CMake configuration registers the native recipe, persistent
fault and loader tests; registration alone is not an execution result.

Fresh current-main integration/full regression, multi-source/masked recipes,
supersampling, broader deformations, portable tangent emission and GPU baking
remain required. Every unfinished original/additional goal row and the later
controller-drawer phase remain active. No system installation, headset launch or
active-session restart occurred.
