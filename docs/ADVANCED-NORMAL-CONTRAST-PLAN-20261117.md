# Advanced normal contrast diagnosis and next CPU forecast

The first actual software view used llvmpipe and matched all four independently
constructed correct ordinary-normal RGB controls with errors 0, 1, 0, 1. The
omitted-normal counterfactual had gaps 3, 4, 1, 6 and therefore failed the required
7 at every original probe. Wrong-domain and swapped-role each had a sensitive
probe. This is a contrast failure, not evidence that the correct renderer is
wrong. The v1 terminal, full log, all 17 images and original hashes remain intact.
A separate wrapper exception about a deleted `lp_dma_buf` allocation masked that
underlying executable exit. Neither result is rewritten or treated as success.

The new CPU-only `--advanced-contrast-forecast FILE` mode uses the exact genuine
17-family construction and unchanged independent advanced normal decoder. It
visits both source and actual second-Bake target, PBR and authored MToon: 68
views. It scans actual 96x96 pixel centres with barycentrics strictly above .05,
requiring the original triangle to be independently frontmost, and retains all
four original probes. JSONL records include the correct, wrong-domain, omitted
and swapped directions and predicted RGB, actual sampled material maps, original
material factors, barycentrics and texture coordinates. Per-view maxima identify
candidate extra interior witnesses; they do not add probes to the GL test.

PBR prediction now uses general GGX with both existing named lights, filtered
linear base and emission, actual metallic, roughness and AO. The ordinary control
has resolved derived maps, so the renderer uses white/unit uniforms and reads the
map values; its original native roughness .8 is not an excuse to assume the
sampled result is 1. The scalar sampler decodes each sRGB texel before bilinear
interpolation, uses the actual constant-UV magnification rule and declared wrap,
and refuses unmodeled prepared-color, overlay, raw-source or unlit routes.
The forecast must first be checked against all sixteen known ordinary-control
RGB triplets from the v1 failed view before using its proposed PBR witnesses.

MToon estimates retain actual typed parameters and sampled base, shade, emission,
coverage, original-role correction and effective native material factors. They
use the established CPU MToon shading reference as a presentation estimate;
expected normals still come from the independent decoder. They are not claimed
as independent RGB acceptance, nor calibrated by the PBR-only failed prefix.
Unsupported animated/scalar/matcap coordinates refuse rather than invent samples.
The next actual GL consumer must independently qualify every suggested witness.

No normal image, Bake recipe, replay authority, source owner, source material or
normal domain is mutated. The existing `--advanced-render` function, native17
fixture, production tree, original four probes, bounds .035 / RGB3 / gap7,
disjoint intervals and all three negatives in every view remain unchanged. No
stronger synthetic normal image is transplanted into the genuine advanced data.

The additive software-v2 wrapper template uses a separate live allocation helper.
It may exclude only the exact offset-zero `rw-s` `/memfd:lp_dma_buf (deleted)`
map, with a positive inode and original proven PID/start/group/session. It reads
four bytes through a matching live child FD/device/inode or the exact live child
mapping address, checks the mapping and process again, and retains the evidence.
ELF magic, executable/private maps, other deleted names, changed identities and
unproven deleted maps refuse. All file-backed ELF paths remain strictly pinned;
unreadable file-backed mappings are refused, not silently skipped. A future
actual corrected run must demonstrate this classification against Mesa itself.
