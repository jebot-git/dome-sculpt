# First creator workspace framing

A first avatar created in a pristine workspace gets one XR overview fit after its accepted mesh is published. The fit uses the actual stereo poses and FoV, including asymmetric/canted views, and both renderer clip planes. It reserves five percent of each actual view edge. It changes only the session canvas translation; model scale/orientation, native geometry/group placement, physical eye/head poses and saved bytes remain intact. Input picking and drawing continue to use the same canvas transform as rendering.

Eligibility belongs to the fresh Document/seed lifecycle. Opening or replacing a project, even with identical bytes, does not qualify. Any prior canvas navigation, including moving away and back, or an edited/undone source disqualifies it. The ordered worker authenticates the first accepted creator work/group; the input worker waits for that exact current mesh and input/source authority. A later source, namespace or navigation change retires the candidate. No global initial-anchor change or repeated head-following fit is added.

Missing or invalid stereo data defers fitting. Non-overlapping projections or a fit outside the renderer clip range leave the presentation unchanged. A desktop-first creation may wait for its first focused XR views. Actual later focus loss or creator cancellation retires a pending fit. A canceled draft never moves the presentation. Initial seed cleanliness and validation retain their original behavior.

The framing cases cover full native Save-byte equality, every real avatar vertex in both projections, varied source/body/hair proportions, off-axis overlap, one-shot behavior, delayed cancellation, desktop-first focus, reopened and authored projects, prior navigation and the +5m joint stress scene. Physical-headset testing remains separate.
