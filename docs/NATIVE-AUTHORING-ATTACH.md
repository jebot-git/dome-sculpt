# Private native project attachment seam

`detail::attach_native_authoring` exposes the existing anonymous attachment body
through a private declaration. The body and native marker/reader meaning are
unchanged. The ordinary GLB path calls that same wrapper. It binds final JSON,
BIN and object remaps to a genuine sealed `NativeAuthoringCapture`; it does not
authenticate caller surfaces through an equivalence flag.

The format-specific compiler must finish its node/mesh/material graph before the
call and preserve existing unique object-node and primitive-material reader
semantics. This is an additive function, with no public data-layout change.

The narrow replacement-TU proof passes Release and owned ASan/UBSan/leaks:
existing native-authoring28, real male19part, and direct-seam6. All six basic and
two real outputs per profile are byte-identical to that profile's unchanged old
archive. The direct seam proves identical ordinary/direct bytes, exact native
recovery, source preservation, cancellation, competing authority and invalid
final remap refusals. Input/archive hashes remain unchanged.

Release support is immutable fresh601/d639. Sanitizer support is B6, with consumed
transitive headers byte-proved and changed Document/input/palette objects absent
from the link maps; this is not a fresh d639 whole-app sanitizer result. Exact
commands and scope are in validation/NATIVE-AUTHORING-ATTACH.json. No new HDR,
SourceUV, typed-VRM capability or main admission follows from this seam.
