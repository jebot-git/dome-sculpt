# Private native/unskinned support continuation

This isolated264 descendant factors the existing owning screened/contact solve
so a separate explicit native input can use current authored deform-bone flags,
current indexed geometry and optional component declarations without an artist
skin or fabricated imported appearance. Empty declarations automatically select
actual connected components and all current deform controls. No native/public
method, UI, ABI, source guard or original imported method is changed/admitted.
No value-near or same-position seam weld is introduced. Common-similarity metric
is still required; full relative-affine staging remains unfinished.

The first actual owning unskinned solve reaches its independent residual and
partition certificates but fails the fixed0.9 own-limb quality threshold:
minimum observed0.818757 on two open disconnected strips. The failure is retained
in artifacts/third-run.log and is not relabeled solved merely because the field
is certified. The all-controls component policy remains a negative control for
the next geometry-derived support candidate. No pose/native/SAN qualification is
claimed. Setup-only initial UV-overlap and zero-length endpoint metadata
refusals are retained separately; their fixtures were corrected without changing
any solver or quality bound.

Build scope: own changed private inline kernel/test and exact264 public headers
against unchanged read-only coherent264 Release core/support archives. This is
not a fresh whole-project build or general robust automatic-weight completion.
Default support must eventually be automatic; optional manual per-component
joint declarations are not a substitute for that objective.
