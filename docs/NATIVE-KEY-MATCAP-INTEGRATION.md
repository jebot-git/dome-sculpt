# Current-key HDR and painted MatCap integration

Runtime `640f05ca38efac2bc08ea89e5459f9f70b9af0c8` combines genuine native36
current-key FLOAT-paint HDR export with painted VRM1 MatCap expressions on the
matching `a0b8a37` application/core/render/support cohort. Only three complete
production translation units change; archive audits in both profiles confirm
that exact member set. All public/private headers, layouts and persistence
versions remain unchanged. This is a private integration milestone, not main
admission, a fresh ALL build or completion of the production objective.

Ordinary HDR package3 now authenticates the real current-frame owner and its
independent writable paint domain. Recovery checks actual emitted positions,
normals, tangents, indices, morph channels/order/names/current weights. Existing
canonical/prepared/typed guards and package4 separation remain. MatCap keeps its
genuine view-normal image/factor/colour-expression semantics and prospective
finite coefficient/work/memory/error bounds; native shaders are unchanged.

The legacy painted-VRM probe retains its original MASK input and adds the same
input without MatCap: both refuse the actual unsupported sampler/domain boundary
with exact caller/file/ordered-Save preservation. A separately declared OPAQUE
input exercises supported shared shade and MatCap colour expressions. Its authored
shift/toony values make both lit and shade terms observable. No emitted output is
rewritten. The independent consumer now handles omitted factor defaults and the
[VRM1 binary threshold](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/expressions.md),
including exact half and adjacent binary32 values. Incorrect inclusive-threshold,
source/paint coordinates, tint, shared shade and MatCap mappings are detected.
