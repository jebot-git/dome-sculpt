## Owning and numerical contract

MatCap is an additive view-normal term independent of the real colour-paint
contribution. Lower and upper primitives sample the same original field. Its
contribution therefore remains unchanged when their coverage is composed. The
compiler bounds the complete supported unit-weight box of preset/custom MatCap
coefficients, including correlated same-expression binds. It requires finite
nonnegative future values in this staged adapter and reserves a conservative
F32 composition margin inside the EXISTING portable error allowance. The margin
uses32 float-rounding operations, the native lighting bound1.25 and the actual
maximum coefficient. Very large or negative staged combinations refuse precisely;
these are adapter limits, not normative restrictions on VRM float4 targetValue.
A64-byte parameter scratch allowance and each parameter visit are charged before
dense image staging. There is no global cache, altered sampler, tolerance change,
clamp or source-only substitute for genuine painted export.

The one complete changed production TU is `vrm1-expression-layer.cpp`. It was
compiled against copied immutable matchingbd3 support. Member multisets and all
member hashes prove only that member changed. Existing private Layer layout and
all public headers are unchanged. This is a matched component proof, not a fresh
whole app/root ABI, GUI or main admission claim. Root canonical/native/prepared/
physical guards must remain during semantic union.
