# Authoring format coordination

These reservations coordinate parallel implementations. A reservation does not
authorize a writer, reader, version-only exemption, or production admission.
Formats must describe actual typed ownership and correspondence, with bounded
validation, persistence, rendering and export evidence. Preserve historical
meanings and reject unsupported capabilities explicitly.

PolygonSources8 is reserved for retaining actual texture sets in source origins;
the version7 bake-recipe meaning stays intact. Polygon surface transfer may use
PolygonSources9 if its trace/normal payload requires another capability. Its
eventual composition must retain the explicit version8 set semantics. The shared
texture-set controller panel uses page31/count32; older private references to
pages31/32 are not current-main allocations.

The existing FrameSet3 prototype only authorizes its stated baseline-expansion
semantics. It does not by itself authenticate changed polygon topology, pose,
normal fields, or writable-paint correspondence. New consumers may reuse a
genuine leaf where its semantics match; they must not relabel a structurally
similar leaf as a different authority.

The polygon implementation must retain the full original paint, material,
deformation, keys, rig and placement while supplying a real current surface
interpretation. Texture sets must have stable set identities and actual
face/corner assignment, independent writable layers and bake/material contexts,
and coherent rendering, querying, persistence and multi-primitive export.

Any public or private layout change requires rebuilding all allocating,
destroying and accessing providers and their consumers together. Equal outer
class sizes do not prove compatibility. Keep prior qualified binaries and their
source/input records intact; qualify the new composition at its actual scope.
