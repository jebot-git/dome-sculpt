# NativeGraphics early-refusal lifecycle diagnosis, 2026-11-11

The 132268 byte/1142 allocation SAN cleanup failure reproduces with ordinary successful UHD offload context work as well as caught early refusal. Explicit successful `eglReleaseThread()` after the process's sole context has been destroyed does not remove it. This rules out early refusal as a necessary trigger and thread release as a demonstrated fix in this setup. It does not establish which provider owns the leak; no product patch or suppression is applied.

The isolated diagnostic compiles the exact frozen b8 `third_party/openbrush/graphics.cpp` and header in full, with ASAN/UBSAN, leak detection 1, strict unsuppressed teardown, current system Mesa26.2.5 and no GL interposer. It has a 30 second/1 GiB process-tree envelope. Source/binary/tool/provider hashes, mapped ELF witnesses, public GL/EGL identity and liveFD evidence are pinned in the companion receipt. All original full-consumer refusal failures remain preserved; these probes cannot replace them.

Each process constructs actual NativeGraphics, queries the actual context, then leaves its normal C++ scope. Refusal modes throw a typed C++ exception after construction and catch it after scope unwinding. Release variants call `eglReleaseThread()` only after proving the fresh process's sole context/display are no longer current. Thus there is no throw across GL's C ABI, observer exit, skipped C++ destructor or global product cleanup policy.

The first matrix retained strict same-node EGLDevice identity. Five Arc modes passed cleanly, including normal/refusal with and without thread release and a distinct-display other-current preservation control. All five UHD modes stopped at a node-identity mismatch before their intended branch, then emitted the same 132268 byte leak. Those failed cases remain in `context-lifecycle-20261111/run-1794402430792961823`; they are not counted as completed release/refusal controls.

The second matrix explicitly records the actual distinction: `GL_RENDERER` is Intel UHD Graphics 770 when requesting UHD, while `EGL_DEVICE_EXT` identifies the surfaceless screen on Arc renderD129. Both Arc129 and UHD128 matching live GPU FDs are present. It validates the actual Arc EGLscreen PCI/device/i915 identity, expected rendering-device PCI/device/i915 identity, exact hardware renderer and both liveFD sets. This is an explicitly paired diagnostic observation, not a weaker replacement for strict Arc authentication. The original full-consumer observer rejects the actual UHD renderer before reaching its later EGLDevice/node checks, so its negative evidence must likewise be described as renderer refusal.

All five Arc cases in the second matrix exit as intended without sanitizer reports. All four UHD cases reach their intended end, record no current display/context after NativeGraphics scope, and record the typed refusal where requested. Both release variants also record successful thread release and default EGL client API afterwards. Nonetheless all four processes abort at exit with the same 132268 bytes/1142allocations. Allocations are attributed to `driConcatConfigs`/`driCreateConfigs` and `drmGetDeviceNameFromFd2`. The invariant failure across ordinary and refusal paths makes offload/screen-config cleanup the next scoped investigation, while exact ownership remains unproven.

The distinct-other-current control preserves a different Arc OpenGL context on a separate device-platform display while the exact surfaceless owner is destroyed, and skips thread release while it remains current. This does not test shared-same-display ownership or all other client APIs. The armor agent's independently found simultaneous renderer/worker `eglTerminate` ownership issue is separate; this diagnosis does not claim that fix resolves this leak.

The second raw runner process exits 0 after writing diagnostic status 1, because the script reports the matrix outcome in JSON rather than its own exit status. Both values are retained explicitly; none of the failed UHD processes is called sanitizer-clean. Evidence is `artifacts/context-lifecycle-v2-20261111/run-1794402945058965619`. The shared Arc lease was held only after root P1 and the armor agent yielded it, then released. No desktop/headset context was disturbed. Hardware is available for the armor agent's short SAN controls.
