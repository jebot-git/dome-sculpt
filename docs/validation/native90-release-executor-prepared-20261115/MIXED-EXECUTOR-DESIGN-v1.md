## Independent readonly staging

Only a whole authenticated object may stage. The executor reads it into a new
exclusive file, verifies source SHA before/after, verifies destination SHA and
records source identities before/after plus the independent destination dev/inode,
size/mode/times. Destination has one link and mode0444. Providers retain their
original bytes, inode and metadata; no provider chmod, hardlink or object edit.
No archive, executable or shared-library product may be staged.

Original raw dependency bytes have an independently copied readonly snapshot at
`execution-native90-v1/provider-depfiles/<owner>.original.d`. Their literal names
and target stay unchanged. There is deliberately NO depfile at the new compiler
output's MD path for a reused owner. Snapshots are not fabricated current compiler
records and are never parsed relative to their snapshot directory. Every one is
parsed using the original actual compiler CWD, with separate current-source and
fresh-generator equivalence evidence. Staging rows say newly_compiled:false.
Partial staging receipts append honestly; interruption never counts a partial
copy as a successfully staged owner. Outputs are retained for diagnosis and the
executor refuses to overwrite them or restart in the same execution namespace.
